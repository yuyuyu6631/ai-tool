## 2024-06-10 - [CRITICAL] Prevent SSRF bypass via alternate IP encoding
**Vulnerability:** The URL validation logic `validate_public_url` in `apps/api/app/services/tool_parser_service.py` was vulnerable to Server-Side Request Forgery (SSRF). While it blocked the `localhost` string and simple private IP strings, it relied on `ipaddress.ip_address(hostname)`, which fails to parse or correctly evaluate alternative IP encodings like hex (`0x7f000001`), integer (`2130706433`), or external domains pointing to localhost (`localtest.me`).
**Learning:** Naive string-based validation or simple IP parsing is insufficient for SSRF protection because attackers can use various encodings or DNS records to bypass the checks and access internal network resources.
**Prevention:** Always perform actual DNS resolution (e.g., using `socket.getaddrinfo`) to get the real IP address before validating against private IP ranges. Additionally, ensure the system "fails closed"—if DNS resolution throws an error (e.g., `socket.gaierror`), explicitly block the request instead of letting it pass.
