## 2025-02-24 - [CRITICAL] 修复 URL 解析器中的 DNS 重绑定导致的服务端请求伪造（SSRF）漏洞
**Vulnerability:** `validate_public_url` 函数存在通过 DNS 操纵进行 SSRF 的漏洞。它只检查了提供的主机名是否看起来像公共 IP 地址，而没有对该主机名执行 DNS 解析以查看它最终映射到哪个 IP（例如，使用像 127.0.0.1.nip.io 这样的服务或使用 0177.0.0.1 等八进制格式）。
**Learning:** 直接验证主机名字符串而不是进行实际的 DNS 解析是不够的。攻击者可以使用解析为内部 IP 的自定义域名（DNS 重绑定/固定），或使用替代的 IP 表示（十六进制、八进制）来绕过简单的字符串验证。
**Prevention:** 始终使用 `socket.getaddrinfo()` 将主机名解析为其底层 IP 地址，并遍历所有返回的 IP 以验证它们中没有指向私有/本地/保留网络。
