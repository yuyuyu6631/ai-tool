## 2024-06-13 - [Fix SSRF vulnerability in tool parser]
**Vulnerability:** The URL parser allowed attackers to supply IPs encoded differently (e.g. integer `127.0.0.1.nip.io`, hex `0x7f000001`) that would bypass the naive SSRF checks in `tool_parser_service.py` because those were string-based `ipaddress.ip_address(hostname)` checks that failed when DNS lookup strings were provided, which fell back to simply returning `parsed.geturl()`. Thus, SSRF attacks were still possible.
**Learning:** SSRF mitigation with `ipaddress` requires accurate IP discovery, which only works if `socket.getaddrinfo` maps the host directly to the IP before verification. When DNS resolution fails or naive string validation throws `ValueError`, it should "fail closed" rather than "fail open" and let the exploit succeed.
**Prevention:** Use `socket.getaddrinfo(hostname, None)` to extract all IPs associated with the given host string, then check each IP with `is_private`/`is_loopback` etc. Also, test assertions against fake URLs should mock `socket.getaddrinfo` to return fake unreserved IP addresses to prevent `socket.gaierror` failures in hermetic environments.
