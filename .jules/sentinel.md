## 2024-07-02 - SSRF 漏洞及 DNS 重新绑定防御
**Vulnerability:** 网页抓取功能 `fetch_webpage_text` 在验证 URL 时，只解析了部分 IP 地址且未能有效拦截所有私有 IP，导致攻击者可以利用 DNS 重新绑定（DNS Rebinding）或配置多条 A 记录的方式绕过内网检测，发起服务端请求伪造（SSRF）攻击。
**Learning:** 在进行网络请求前验证目标域名时，必须强制解析该域名，并遍历其返回的所有 IP 地址进行严格的黑名单过滤。不仅如此，如果域名解析失败，必须采用“默认拒绝（Fail Closed）”策略，而不能放行，否则攻击者可利用不存在或特殊的域名绕过检测。
**Prevention:** 验证用户提供的 URL 时，使用 `socket.getaddrinfo` 获取所有解析的 IP。对于所有 IP 进行私有/局域网地址校验。捕获 `socket.gaierror` 等解析异常，并主动抛出错误以阻断请求。同时为单元测试中的模拟域名配置专门的 Mock 拦截，以保持测试的稳定与隔离性。
