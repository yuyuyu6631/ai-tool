# 最新 PRD 上线落地计划

> 本文档用于把最新 `doc/prd.md` 从产品目标拆成研发、运营、测试和迭代可执行计划。  
> 当前实现事实以 `../docs/current-implementation-baseline.md` 为准。  
> 最后更新：2026-05-13。

## 1. 上线目标

最新 PRD 的核心目标是把星点评从“AI 工具发现/推荐站”推进为：

**面向互联网公司工作场景的 AI 工具使用经验社区。**

第一阶段上线不追求完整社区，而要先跑通可验证闭环：

```text
首页/搜索 -> 任务场景 -> 经验内容 -> 工具详情 -> 免费福利 -> 登录/收藏/发布入口
```

验收时不要只看页面数量，要看用户是否能围绕一个具体任务完成“找工具、看经验、领福利、沉淀资产”的路径。

## 2. 当前实现对齐

### 2.1 已具备的基础

当前代码已经具备以下能力，可以作为新 PRD 的工程底座：

- 首页 `/`
- 任务场景入口 `/tasks`
- 场景列表与详情 `/scenarios`、`/scenarios/[slug]`
- 工具目录和工具详情 `/tools`、`/tools/[slug]`
- 经验社区静态入口 `/experiences`、`/experiences/[id]`
- 免费福利入口 `/deals`、`/benefits`
- 搜索页 `/search`
- 登录注册 `/auth`
- 后台工具、评论、榜单、匹配方案管理
- 后端工具、场景、评论、认证、AI 搜索、推荐和后台 API

这些入口说明代码方向基本可承接新 PRD，但当前仍有明显差距。

### 2.2 主要缺口

| PRD 模块 | 当前状态 | 必须补齐 |
| --- | --- | --- |
| 任务场景 | 已有 `/tasks`、`/scenarios`，但场景与经验、福利的关系仍弱 | 场景页聚合相关经验、工具、福利 |
| 经验社区 | 前端已有静态样例页 | 后端模型、API、发布、审核、详情数据、互动数据 |
| 免费 AI 福利 | `/deals` 仍基于免费工具列表 | 独立福利模型、福利详情、有效期、领取状态、验证状态 |
| 工具详情 | 已有工具信息、评论和相似工具 | 相关经验、相关福利、官方工具标识和收藏入口 |
| 收藏/个人中心 | 登录存在，收藏与个人中心未闭环 | 统一收藏、我的收藏、我的发布、浏览历史 |
| 发布经验 | 当前只有入口心智 | 发布表单、草稿、预览、审核状态 |
| 后台运营 | 工具/评论/榜单/匹配已有 | 经验内容管理、福利管理、官方精选、审核流 |
| 搜索 | 工具和 AI 搜索已有 | 综合搜索结果按任务、工具、经验、福利分组 |

## 3. 研发实施计划

### 3.1 P0：最小闭环上线

P0 目标：用户不依赖后台复杂能力，也能完整体验任务经验社区的核心路径。

#### 前端

1. 首页信息架构调整  
   突出任务场景、经验社区、免费福利和星启生态入口，避免首屏仍像工具目录。

2. 任务场景页增强  
   每个任务场景展示：
   - 任务说明
   - 相关经验
   - 适用工具
   - 相关福利
   - 相似任务

3. 经验社区最小动态化  
   将 `/experiences` 和 `/experiences/[id]` 从纯静态样例升级为可由 API 返回的数据渲染。前端保留静态 fallback，避免 API 失败时页面空白。

4. 免费福利页重构  
   `/deals` 保留为福利入口，新增或复用 `/benefits` 承接福利列表与详情。福利卡片必须展示工具、类型、有效期、领取状态和限制摘要。

5. 工具详情页补关联模块  
   增加“相关经验”和“相关福利”，并支持官方工具标识。

6. 登录引导统一  
   收藏、发布、点赞、评论等未登录操作都跳转 `/auth`，并保留返回路径。

#### 后端

新增最小数据对象：

```text
experience_posts
experience_post_tools
experience_comments
benefits
benefit_tools
favorites
browsing_history
content_moderation_records
```

P0 可以先不做复杂推荐算法，但必须保证核心关系清楚：

- 经验帖关联任务场景和工具
- 福利关联工具和任务场景
- 收藏支持工具、经验帖、福利三类对象
- 发布经验有状态：draft、pending_review、published、rejected、archived
- 福利有状态：active、ending_soon、expired、archived

#### API

P0 API 最小清单：

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/experiences` | 经验帖列表，支持任务、工具、精选、排序筛选 |
| GET | `/api/experiences/{id}` | 经验帖详情 |
| POST | `/api/experiences` | 登录用户发布经验草稿或提交审核 |
| PUT | `/api/experiences/{id}` | 作者编辑草稿 |
| GET | `/api/benefits` | 福利列表，支持工具、任务、有效期、状态筛选 |
| GET | `/api/benefits/{id}` | 福利详情 |
| GET | `/api/me/favorites` | 我的收藏 |
| PUT | `/api/me/favorites` | 收藏或取消收藏 |
| GET | `/api/me/posts` | 我的发布 |
| GET | `/api/search` | 综合搜索结果，按任务、工具、经验、福利分组 |
| GET | `/api/admin/experiences` | 后台经验管理 |
| PUT | `/api/admin/experiences/{id}` | 审核、精选、下架经验 |
| GET | `/api/admin/benefits` | 后台福利管理 |
| POST | `/api/admin/benefits` | 新增福利 |
| PUT | `/api/admin/benefits/{id}` | 编辑、验证、下架福利 |

## 4. 运营落地计划

### 4.1 内容冷启动

第一批内容不等用户投稿，由官方运营账号发布。

建议首批覆盖 9 个一级任务场景，每个场景至少准备：

- 5 个工具
- 3 篇经验帖
- 1-3 条福利或试用入口

优先顺序：

1. 文档写作：PRD、方案、会议纪要、标书
2. 内容生产：选题、文案、脚本、标题
3. 代码开发：代码生成、Bug 定位、接口文档
4. 数据分析：用户反馈分析、指标归因
5. 客户方案：客户背景整理、销售话术、售前方案
6. 竞品调研：功能对比、市场分析、用户评价分析
7. 自动化效率：表格处理、批量整理
8. 图片/视频生成：海报、配图、短视频脚本
9. 智能体搭建：知识库助手、客服助手、流程编排

### 4.2 内容模板

经验帖必须按固定结构录入：

- 标题
- 适用任务
- 使用工具
- 适用岗位标签
- 使用前准备
- 操作过程
- 输出效果
- 使用心得
- 可复用要点
- 避坑提醒

福利必须按固定结构录入：

- 福利名称
- 对应工具
- 适用任务
- 福利类型
- 有效期
- 领取状态
- 是否验证
- 领取方式
- 使用限制

### 4.3 数据看板

后台或运营报表至少追踪：

- 任务场景点击率
- 经验帖阅读量
- 工具详情访问量
- 收藏率
- 福利领取点击率
- 发布经验数
- 福利有效率
- 次日和 7 日回访率

## 5. 测试验收计划

### 5.1 单元和集成测试

前端：

- 经验列表筛选和空状态
- 经验详情结构渲染
- 福利列表筛选、过期状态和空状态
- 工具详情相关经验/福利模块
- 未登录收藏和发布跳转
- 个人中心收藏列表

后端：

- 经验帖列表、详情、发布、审核状态流转
- 福利列表、详情、有效期和状态流转
- 收藏三类对象的幂等操作
- 权限校验：未登录、普通用户、运营、管理员
- 综合搜索分组返回
- 后台经验和福利管理

### 5.2 E2E 验收路径

上线前必须覆盖这些路径：

1. 首页 -> 任务场景 -> 经验详情 -> 工具详情 -> 福利详情
2. 首页搜索任务 -> 综合搜索结果 -> 经验详情
3. 工具详情 -> 相关经验 -> 经验详情
4. 工具详情 -> 相关福利 -> 福利详情
5. 未登录点击收藏 -> 登录页 -> 登录后回到原页面
6. 登录用户收藏工具、经验、福利 -> 个人中心查看
7. 登录用户发布经验 -> 待审核
8. 运营后台审核经验 -> 前台展示官方精选
9. 运营后台新增福利 -> 前台展示 -> 领取点击统计

### 5.3 上线验收口径

上线前必须满足：

- 首页第一屏能明确传达“任务场景 + 经验社区 + 免费福利”
- 任务场景页不是空分类，至少有经验、工具和福利任意两类内容
- 经验详情页能完整展示 PRD 要求的内容结构
- 福利详情页能展示领取方式、有效期和使用限制
- 工具详情页能反向关联经验和福利
- 未登录和权限错误都有清楚提示
- 移动端主要路径不横向溢出、不遮挡按钮
- 公网 `/xingdp/` 子路径下所有新路由、静态资源和 API 都可访问

## 7. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 经验内容质量不足 | 初期以官方运营内容冷启动，用户投稿必须审核 |
| 福利过期损害信任 | 福利必须有有效期、验证状态和过期自动降级 |
| 工具库仍像导航站 | 工具详情必须关联任务、经验和福利 |
| 后台复杂度过高 | 先做轻量管理，审核流只覆盖经验和福利 |
| 搜索结果混乱 | 先按类型分组，不急于做复杂排序 |
| 星启生态入口过重 | 官方工具自然进入工具库和经验内容，避免强广告化 |
| 个人中心范围失控 | 第一版只做收藏、发布、浏览历史入口 |

## 8. 完成定义

一次“按最新 PRD 上线”不能只以部署成功为完成标准。必须同时满足：

1. 用户能从首页进入任务场景、经验社区、工具库和免费福利。
2. 用户能围绕一个任务看到相关经验、适用工具和福利。
3. 工具详情能展示相关经验和福利。
4. 登录用户能收藏工具、经验和福利。
5. 运营能维护经验和福利内容。
6. 测试覆盖核心路径和权限边界。
7. 公网子路径 `/xingdp/` 验收通过。
8. 文档中的“当前实现”和“规划中”保持区分。
